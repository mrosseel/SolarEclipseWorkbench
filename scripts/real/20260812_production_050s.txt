# Generated by scripts/generate_20260812_production.py - edit that, not this file.
#
# Body   : Fuji Fujifilm X-T4   (Fuji SDK + relay trigger on the remote jack)
#          The Canon EOS 800D is parked; its half of this schedule is in
#          scripts/test/20260812_production_EOS800D.txt, still interleaved with the
#          frames below in case the pair runs again on a second machine.
# Optics : 80/480 mm refractor, fixed f/6.  The body cannot drive a telescope's
#          aperture, so the aperture column says '-' and the setting is skipped.
#          The f/6 still sets every exposure below; it just is not sent to the body.
# Filter : Baader AstroSolar PHOTOGRAPHIC film (ND 4.0) on the scope, for every
#          partial-phase frame.  NOT the ND 5.0 visual film - never look through this.
#
# At f/6 with photographic film the sun wants 1/7139 just after C1 at ISO 100, which
# the X-T4 reaches at its 1/8000 ceiling.
#
# Site   : Palencia, N Spain  42.0095 N, -4.5289 E, 740 m
# Type   : Total, magnitude 1.0119, totality 100 s
#
#   C1     17:33:56 UTC   sun  19.0 deg
#   C2     18:29:07 UTC   sun   8.8 deg
#   MAX    18:30:00 UTC   sun   8.7 deg
#   C3     18:30:47 UTC   sun   8.5 deg
#   C4     19:22:34 UTC   sun  -0.2 deg
#   sunset 19:22:53 UTC
#
# Sunset eclipse: totality is only 8.7 deg up and the sun sets 19 s after C4, so the
# last partials are shot into horizon haze.  A clear, low western horizon matters more
# here than anything else.
#
# Which command does what on this body
# ------------------------------------
#   corona ladders  take_hdr ramps the shutter between frames on gphoto2, but on the
#                   Fuji SDK path it fires 2*stops+1 frames at ONE speed.  The X-T4
#                   uses take_bracket (wired to the SDK bracket_no_download) instead.
#   contact bursts  the relay on the remote jack free-runs CH at ~8 fps, which the
#                   SDK cannot do at all: it returns 0x1008 with the dial on CH.
#
# Atmospheric dimming
# -------------------
# The sun falls from 19.0 deg at C1 to the horizon and airmass climbs from 3.1 to over
# 30, so every filtered frame was computed for the sun altitude at that exact instant:
#   - above 5 deg : Jubier tables, interpolated in sun altitude and site height
#   - below 5 deg : the tables break down, so the 5 deg value is extrapolated with a
#                   Kasten-Young airmass and 0.25 mag/airmass extinction.
# That coefficient is a guess (0.15 clear .. 0.40 hazy) and the error grows to several
# stops at the horizon, hence the wide brackets after C3+18m.  Comments carry the sun
# altitude and airmass X used for each frame.
#
# Partial-phase frames alternate between the bodies, so the pair samples the disc
# twice as often as either alone.
#
#
# PRE-FLIGHT - every item by hand, before C1, then do not touch the body again
# =========================================================================
# The SDK cannot read most of these back, so nothing below is verified at run
# time.  An unticked box is a silent failure: the frames look normal.
#
#   BODY, set and then left alone
#   [ ] drive dial on CH          a burst free-runs at ~15 fps; on Single each
#                                 contact is one frame and the beads are lost
#   [ ] shutter speed dial on T   or the script cannot set the speed at all
#   [ ] ISO dial on C             or every ISO the script asks for is ignored
#   [ ] mode dial on M            metering off a black sky ruins every corona frame
#   [ ] focus selector on M       AF refuses S2 whenever focus does not confirm;
#                                 the SDK reads this back as 0x1002, unverifiable
#   [ ] image quality RAW only    a JPEG alongside doubles buffer use and triples
#                                 the time per frame; reads back 0x1013, unverifiable
#   [ ] exposure compensation 0
#   [ ] long-exposure NR off      it doubles the time of every frame past 1s
#   [ ] IS / OIS off              on a tripod it hunts
#   [ ] power save off            a sleeping body misses its cue and cannot be woken
#   [ ] PC CONNECTION MODE = USB TETHER SHOOTING FIXED, not card reader
#   [ ] card formatted, battery full, spare battery within reach
#
#   RIG
#   [ ] solar filter ON and secure - it comes off only between C2 and C3
#   [ ] focus set on the limb at high magnification, then taped or locked
#   [ ] PREVIEW EXP./WB IN MANUAL MODE = ON, or live view shows a
#       normalised image and its histogram says nothing about exposure
#   [ ] framing allows for drift across the whole of totality
#   [ ] clear, low western horizon - the sun sets 19 s after C4
#
#   SOFTWARE, in this order
#   [ ] detect the camera
#   [ ] connect the relay (S2 = channel 2, S1 = channel 1)
#   [ ] load this script LAST - commands bind to their devices at load time,
#       so a relay connected afterwards leaves every relay_* line skipped and
#       the X-T4 loses both contact bursts
#   [ ] run the relay smoke test below and confirm the body actually fires
#   [ ] check the clock: sync_cameras runs at C1-20m and again at C1-2m
#
#   STILL UNTESTED - bench these before the day
#   [ ] firing the remote jack while the SDK holds the session
#   [ ] the whole script through the scheduler rather than command by command

#
# This file fills 50 s of totality: 3 corona ladders of 7 frames, the first
# 8.5 s after C2 and the last finishing 6.0 s before C3.  Load it only when Solar

# at less than that the last ladder is still exposing when the sun comes back.
#
# Everything inside a minute of a contact - the bursts and the spoken countdown -
# is scheduled against the limb-corrected moments, because that is when totality
# actually begins and ends.  The cues further out stay on the mean contacts, where
# a few seconds is nothing and not depending on the limb profile is worth more.
#
# The bead bursts are scheduled against the edges of the limb-corrected bead
# window, not against the contacts.  A smooth-Moon C3 is 3.5 s later than the real
# one here, which is most of a burst.  These lines need the lunar limb profile

# Solar Eclipse Workbench says so when the script is loaded.
#

# Owner's specification: the SMALL diamond - 'one or two beads left' - on the

# contacts; the crescent side gets the remainder of the hold.  Bursts drain
# their tether queue live, so a hold is no longer capped at 32 frames.
